# Lost&Found — current scope

The app is mobile-only (Android/iOS). The previous React/Vite workspace, browser tests, web dependencies and web export/deployment commands have been removed. Backend and Supabase remain required. Display branding is Lost&Found; technical package/import identifiers remain compatible.

Implemented: Supabase email/password auth, lost/found drafts and publishing, camera/gallery, GPS, private compressed images, report editing, search, matching with 40/30/20/10 weights, Gemini adapter and editable descriptions, in-app notifications and Expo push adapter, ownership challenge/attempt limit, private text/image/system chat. Profile → Staff desk now supports organization reports, storage assignment, conversation and confirmed physical handover. API authorization and database permissions remain authoritative.

Same-account reports are intentionally excluded from matching. Use two users as documented in README. Apply migration 002 for GPS-only reports and invalidation of stale proposed matches; no schema reset is needed.

Remaining work includes native email-recovery deep links/new-password flow (the former web recovery screen was removed), genuine visual embeddings/matching quality evaluation, image deletion/pagination/full filter UI, dispute escalation after lockout, mobile organization/staff administration and analytics, QR/deep links and other V2 features, deletion/retention policy and production monitoring. Email reset requests exist but end-to-end recovery is not yet supported by the mobile app.

Hosted Gemini/SMTP/Realtime and device push require real credentials and separate validation. Android/iOS device behavior, signing, store releases, load/latency/uptime and restore targets remain unverified. Native JS export is not an APK/IPA build or device test.

Backend/shared production npm audit previously reported no known vulnerabilities after upgrading sharp. Expo tooling has unresolved transitive advisories and needs a coordinated remediation before store/production releases. Docker image dependency downloads could not complete in the onboarding machine; do not claim the container image is validated.

GPS can be the report location without a registered venue. Its coordinates are shown to the author and used to rank suggestions, while public projections omit exact coordinates. Selecting a venue replaces GPS and vice versa; optional reverse geocoding only supplies a city/district label. Distance does not exclude candidates in the current permissive MVP.

Matches are grouped by the caller's own report; finder and owner see the opposite report in each pair. Duplicate match IDs and rejected pairs are not displayed. LOST/FOUND is the report type; “Possible match — unverified” is a suggestion status, not proof of a find or return. The current permissive MVP requires one shared non-filler word in user-written name/description. A shared color word counts; completely disjoint text remains Searching. Existing PROPOSED suggestions are reconciled on report/match reads, but VERIFYING/VERIFIED/RETURNED history is not retroactively rewritten. The system does not change an author's report type based on AI.

Manual claims / diagnostics (migration 004 after 003): `POST /reports/:foundId/claim` takes `{lost_report_id}` owned by the caller. Both reports must be available, opposite types and different authors; it creates an unverified MANUAL suggestion without claiming an AI percentage. Explicitly rejected pairs cannot be reopened. Private ownership challenge, verification limits and return permissions remain required. Algorithm reconciliation skips manual suggestions. `GET /reports/:id/diagnostics` is author-only and shows AI configuration/state, sanitized job errors and rejection reasons against the latest 100 available found reports; no other user's private coordinates, description or AI evidence are returned. Hosted Gemini calls and phone interactions require verification in the user's environment.

Current policy (005 supersedes earlier strict matching): category, distance, time and the 70-point threshold no longer exclude candidates; the original weights only rank text-overlap suggestions. Opposite report types, different authors and available statuses remain required. Publication/recheck performs text matching before the background Gemini call. Migration 005 queues existing available reports again; algorithm withdrawals may revive but explicit user rejections remain final. POST /ai/check runs an authenticated live text probe with the server model/key; it does not prove image analysis succeeds. Actual hosted Gemini success remains unverified without the user's provider access.
